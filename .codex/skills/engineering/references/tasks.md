# Tasks

Decompose approved requirements into executable work without introducing a second interpretation layer.

## Procedure

1. Start from the approved goal/specification.
2. Map Goal → Epic → Story → Task only to the depth useful for the work.
3. Make dependencies and parallelizable boundaries explicit.
4. Give each task a concrete outcome and verification method.
5. Keep task wording aligned with the requirement; unresolved product/design questions go back upstream.

## Guardrails

- Task generation is downstream of requirements.
- Do not create work for speculative cleanup.
