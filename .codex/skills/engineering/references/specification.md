# Specification

Turn approved intent into explicit behavior and acceptance criteria. This reference covers generic specifications and repository-defined specification formats.

## Procedure

1. Identify actors, inputs, outputs, state changes, permissions, and failure behavior.
2. Separate current behavior, requested behavior, and assumptions.
3. Define edge cases and precedence rules that affect implementation.
4. Make acceptance criteria observable and testable.
5. Render the result in the requested generic format without changing the underlying requirements.

## Guardrails

- Do not let document format reinterpret approved behavior.
- Follow repository-defined specification tooling when present; do not create a competing automatic route for document format alone.
