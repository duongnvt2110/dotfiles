# Intake

Clarify only what is actually unresolved. Repository evidence should answer repository questions before the user is asked to repeat discoverable information.

## Procedure

1. Identify the requested outcome and concrete success criteria.
2. Inspect repository, docs, and available tools for facts that can be discovered directly.
3. Normalize ambiguous terminology and state the interpretation being used when it matters.
4. Surface only decisions that materially affect behavior, scope, architecture, or safety.
5. Ask the smallest number of targeted questions needed; otherwise proceed with explicit assumptions.

## Guardrails

- Do not turn clarification into its own automatic route.
- Do not ask for information already available from the repository or tools.
- Use `$brainstorming` when the user explicitly wants collaborative design exploration.
- Use `$goal-griller` when the user explicitly wants a vague task converted into a verifiable execution goal.
